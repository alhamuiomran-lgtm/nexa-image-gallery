Update, back up and recover

Before an update

  1. Keep the current theme and Companion archives.
  2. Back up the database and files, including uploads and child-theme changes.
  3. Confirm the restore procedure on staging.
  4. Read the release notes and required theme/plugin version pairing.

Apply the matching release

Update on staging first. Use WordPress’s theme and plugin upload/update screens with the supplied installable archives. Keep customer edits outside product directories. Clear relevant caches, then check Studio, custom blocks, requests, navigation and representative pages.

Rollback

If the release notes declare a data migration, follow its recovery instructions. Restore the matching files and database backup together when required. Replacing a ZIP alone may not reverse a data migration. Do not delete or reset customer tables as a troubleshooting step.

Current qualification

Consult RELEASE-STATUS.json and QA/package-lifecycle.json for the native exact-archive install, upgrade, data-preservation and rollback results. This candidate makes no database schema migration; restored product files do not replace a database backup. Back up both anyway. No automatic update server, purchase-code validation or third-party updater is promised by this guide.
